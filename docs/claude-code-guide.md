## 한 줄 요약

**클로드 코드는 한 줄씩 자동완성해 주는 도구가 아니라, 기능·파일·버그를 통째로 맡기는 "에이전트형" AI 동료예요.**
그리고 잘 쓰는 비결은 두 가지예요.

1. **맥락(컨텍스트)을 많이 줄수록 똑똑해진다** → CLAUDE.md
2. **스스로 결과를 확인할 수단을 주면 알아서 반복해서 완성도를 올린다** → 테스트·스크린샷·검사 스크립트

## 02. 구간별로 본 클로드 코드의 장점 💡

### ① 완전한 에이전트형 + 어떤 환경에서도 동작 (1:25)
- 예전 AI 코딩 도구는 **한 줄씩 자동완성** 위주였는데, 클로드 코드는 **기능·함수·파일 전체, 버그 전체**를 맡는 도구예요.
- VS Code, Xcode, JetBrains, Vim… **어떤 편집기를 쓰든, 어떤 터미널이든** 그대로 쓸 수 있어요. 원격 SSH, tmux에서도 OK.
- 정해진 사용법을 강요하지 않는 **"파워 툴"** 이라서, 처음엔 뭘 입력해야 할지 막막할 수 있어요 → 그래서 ②번부터!

### ② 처음 켜고 해 둘 세팅 (2:56)
- `/terminal-setup` : `Shift + Enter` 로 줄바꿈
- `/theme` : 라이트·다크 모드
- `/install-github-app` : 깃허브 이슈·PR에서 `@claude` 로 부르기
- **자주 묻는 권한은 미리 허용** 해 두면 매번 승인 안 눌러도 됨
- 🎤 **꿀팁: 받아쓰기(음성 입력)** — 맥은 설정 > 손쉬운 사용 > 받아쓰기를 켜고, 키 두 번 누르고 말로 지시. 길고 구체적인 프롬프트를 쉽게 줄 수 있어요.

### ③ 내 코드에 질문부터 (4:19) ⭐
- 보리스가 **"무엇보다 먼저"** 추천하는 사용법이에요.
- 앤트로픽은 신입 개발자 첫날 클로드 코드를 설치하고 바로 코드베이스에 질문하게 한대요. 그 결과 **온보딩 기간이 2~3주 → 2~3일**로 줄었어요! 😮
- **색인(인덱싱)을 안 해요.** 코드를 어디 업로드하지 않고 내 컴퓨터에만 있어요. 생성 모델 학습에도 쓰지 않아요. 그래서 **설치하자마자 바로** 써요.
- 단순 텍스트 검색이 아니라 "이 클래스는 어디서 어떻게 쓰여?" 하면 **실제 사용 예시까지 찾아서** 위키처럼 답해 줘요.

### ④ 바뀐 기록·이슈까지 물어보기 (6:04)
- "이 함수는 왜 인자가 15개고 이름이 이상해?" → **Git 기록을 뒤져** 누가, 언제, 어떤 이슈 때문에 바꿨는지 요약.
- 깃허브 이슈도 웹으로 가져와서 맥락을 파악해요.
- 보리스는 **매주 월요일 회의 전에 "이번 주에 내가 뭐 했어?"** 라고 물어서 정리본을 그대로 붙여 넣는대요. 👍
- 📌 처음엔 **도구·코드 수정보다 질문부터**. 그래야 프롬프트 쓰는 법과 "어디까지 한 번에 맡겨도 되는지" 감이 생겨요.

### ⑤ 고치기 전에 계획부터 (7:53)
- 클로드 코드의 도구는 몇 개 안 돼요(파일 수정, 명령 실행, 파일 검색). 알아서 조합해서 탐색 → 구상 → 수정까지 해요.
- 큰 기능을 한 번에 시키면 **엉뚱한 걸 만들 때**가 있어요. 가장 쉬운 해결책:
  > **"코드 쓰기 전에 계획부터 세우고 나한테 확인받아."**
- 특별한 모드를 안 써도 이렇게 말만 하면 돼요.
- 🪄 보리스의 단골 주문 **"commit push"** — 브랜치 만들고, 기존 커밋 형식을 알아서 따라 커밋하고, 푸시하고, PR까지 올려 줘요.

### ⑥ 우리 팀 도구 연결하기 (9:55)
- 두 가지 방법: **① 명령어(CLI) 도구** — "이 도구 써, 사용법은 `--help` 봐" 하면 알아서 익혀 씀 / **② MCP 서버** 연결.
- 자주 쓰면 CLAUDE.md에 적어 두면 다음 대화에서도 기억해요.

### ⑦ 자주 쓰는 작업 순서 3가지 (11:02)
1. **탐색 → 계획 → 확인받고 → 코딩**
2. **테스트 먼저** 쓰고 통과하게 만들기
3. **목표 이미지(시안)와 스크린샷 비교**하며 고치기

👉 2·3번이 특히 강력한 이유: **클로드가 스스로 결과를 확인할 수단**이 있으면 2~3번 알아서 반복해서 **거의 완벽하게** 맞춰요. 분야가 뭐든 "결과를 볼 방법"을 주세요!

### ⑧ CLAUDE.md로 맥락 주기 (12:17) ⭐ 가장 중요
> **"맥락을 더 줄수록 결정이 더 똑똑해진다."**

| 위치 | 용도 |
|---|---|
| 프로젝트 폴더 `CLAUDE.md` | 매 대화 시작 때 자동으로 읽음. **깃에 올려 팀과 공유** |
| `CLAUDE.local.md` | 나만 쓰는 규칙 (깃에 안 올림) |
| 하위 폴더 `CLAUDE.md` | 그 폴더에서 작업할 때만 자동으로 읽음 |
| 회사(엔터프라이즈) 공용 | 모든 저장소에 자동 적용 |

- 적을 것: 자주 쓰는 명령어, 쓰는 도구, 구조 결정, 중요한 파일, 스타일 가이드
- ⚠️ **짧게 유지!** 길면 맥락 공간만 차지하고 별 도움이 안 돼요.
- `.claude/commands/` 에 **나만의 슬래시 명령어**를 만들 수 있어요. 클로드 코드 팀은 `/label-github-issues` 같은 명령으로 이슈 분류를 자동화한대요.
- `@파일명` 으로 파일을 바로 맥락에 넣을 수 있어요.

### ⑨ 팀과 설정 나누기 (15:50)
- CLAUDE.md뿐 아니라 **권한·슬래시 명령어·MCP 설정**도 "프로젝트용 / 나만 / 전체 공용"으로 나눠 둘 수 있어요.
- 예) 팀 모두 쓰는 테스트 명령은 **자동 허용**, 절대 열면 안 되는 주소는 **차단**.
- `.mcp.json` 을 깃에 올려 두면 그 저장소에서 클로드를 켜는 사람 모두에게 MCP 설치를 안내해요.
- 뭘 써야 할지 모르겠으면? **팀 공유 프로젝트 맥락(CLAUDE.md)부터.** 한 사람이 조금 적어 두면 팀 전체가 혜택을 받아요.
- `/memory` 로 지금 어떤 기억 파일들이 불러와졌는지 보고 고칠 수 있어요.

### ⑩ 꼭 알아 둘 단축키 (18:44)
| 키 | 기능 |
|---|---|
| `Shift + Tab` | 모드 전환 (수정 자동 수락 / 계획 모드 등). 테스트 반복처럼 방향이 맞을 땐 자동 수락이 편해요 |
| `#` (영상 당시) | "이거 기억해" → CLAUDE.md에 자동 추가. 지금은 그냥 **"이건 기억해 줘"** 라고 말해도 돼요 |
| `!` | 셸 명령 바로 실행. **결과가 클로드에게도 보여요** |
| `@` | 파일·폴더 지정 |
| `Esc` | 언제든 멈추기. **눌러도 작업이 망가지지 않아요.** 20줄 중 1줄만 고치고 싶을 때 멈추고 말해 주기 |
| `Esc Esc` | 이전 시점으로 되돌아가기 |
| `claude --resume` / `--continue` | 이전 대화 이어서 하기 |
| `Ctrl + R` | 클로드가 보는 전체 출력 보기 |

### ⑪ 다른 프로그램과 함께 쓰기 – SDK (20:52)
- `claude -p "질문"` = 클로드 코드가 쓰는 것과 **똑같은 SDK**.
- 허용할 도구, 출력 형식(JSON, 스트리밍 JSON)을 지정할 수 있어요.
- 앤트로픽은 **CI, 장애 대응, 각종 파이프라인**에 매일 써요.
- **"초지능 유닉스 유틸리티"** — `git status | claude -p ...`, 긴 로그를 파이프로 넣고 "여기서 이상한 점 찾아 줘" 같은 사용이 가능해요.

### ⑫ 여러 개 동시에 돌리기 (22:37)
- 보리스 본인은 보통 한 번에 하나(저장소별 탭 몇 개)를 쓴대요.
- 파워 유저는 **같은 저장소를 여러 개 체크아웃**하거나 **git worktree**로 분리해서 여러 클로드를 **병렬로** 돌려요. SSH, tmux도 활용.

### ⑬ 질의응답에서 나온 알짜 정보 (23:26)
- **가장 어려웠던 부분:** 셸 명령을 안전하게 실행하는 것. 읽기 전용 명령 구분, 정적 분석, **단계별 허용·차단 권한 시스템**으로 해결.
- **이미지도 이해해요 (멀티모달):** 드래그 앤 드롭, 파일 경로, 붙여넣기 모두 OK. 시안 이미지를 넣고 "이대로 구현해" 하면 스크린샷 비교하며 반복해서 완성.
- **왜 IDE가 아니라 터미널?** 사람마다 쓰는 편집기가 달라서 공통분모인 터미널로. 그리고 모델이 너무 빨리 좋아져서 화면(UI)에 과투자하지 않으려고.
- 앤트로픽 기술직의 **약 80%가 매일** 클로드 코드를 쓴대요. 연구자들은 노트북(Jupyter) 편집·실행에도 써요.

## 04. 그래서, 우리 저장소(glasses-images)에는 이렇게 적용했어요 ✅

| 영상의 팁 | 이 저장소에 적용한 것 |
|---|---|
| ⑧ CLAUDE.md로 맥락 주기 (짧게!) | `CLAUDE.md` — 폴더 구조, 파일명 규칙(`YL134-C4.jpg`), 규격, 커밋 형식, 블로그 말투 |
| ⑦ 스스로 확인할 수단 주기 | `scripts/check_images.py` — 파일명·크기(1000×1000 / 가로 780px)·RGB·용량(500KB)을 자동 검사. 클로드가 이미지를 고친 뒤 **통과할 때까지 스스로 반복** |
| ⑧ 나만의 슬래시 명령어 | `.claude/commands/upload-image.md` → **`/upload-image moodframe 파일들`** 한 줄이면 검사 → 1장당 1커밋 → URL 표 정리까지 |
| ⑤ 고치기 전에 계획부터 | "여러 장 바꾸는 작업은 계획 먼저 보여주기" 규칙 |
| ⑬ 안전한 실행 | "삭제·덮어쓰기 전 반드시 확인" 규칙 (쿠팡에 걸린 이미지 주소가 깨지지 않도록) |
| ⑨ 팀과 공유 | 전부 깃에 올려서 어느 컴퓨터·어느 세션에서 클로드를 켜도 같은 규칙 적용 |
